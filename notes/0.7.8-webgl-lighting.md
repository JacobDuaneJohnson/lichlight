# v0.7.8 draft — hybrid WebGL2 lighting

Not a release. `VERSION` in `index.html` stays `0.7.7` until `release.sh` bumps it. Do not tag, merge, or publish to GitHub Pages from this branch.

## What plays

The world, particles, sprites, and UI still draw on the Canvas 2D context (`ctx` / `#game`). Lighting is the only part that can leave that context.

Each frame, after the world draw and before emissive sprites:

1. `gatherLights` builds the same light list as before (`frameLights`). `lightAt` (eyes in the dark, dust motes) still tests those polygons in JS.
2. **WebGL2 path** when all of these are true:
   - GL LIGHT is `AUTO` or `ON` (pause / title menu)
   - Lighting quality is **High** (Low always stays on the Canvas lightmap)
   - `webgl2` exists and the shader linked
3. Otherwise the existing `lcan` lightmap is filled and multiplied over the scene, including half-resolution on Low.

The shader writes a light image (ambient, explored memory, additive lights, Bayer dither), multiplies it by the 2D scene, then `drawImage`s that result back onto `#game`. `drawEmissive`, bloom, vignette, and the HUD run after that, on `ctx`, so flames, eyes, motes, and sparkles stay above the darkness.

## Toggle

| GL LIGHT | Lighting quality | Result |
| --- | --- | --- |
| AUTO | High | WebGL2 if the context works, else `lcan` |
| ON | High | same as AUTO (ON does not invent a context) |
| OFF | High | Canvas `lcan` |
| any | Low | Canvas `lcan` (half-res) |

Phones auto-pick **Low** (`pointer: coarse`), so an iPhone stays on the Canvas lightmap until Lighting is set to High. GL LIGHT is saved in the same settings object as sound and shake.

Test hooks (not shown in the menu): `window.__noWebGL = true` or `window.__forceCanvasLight = true`.

`game.lightPath()` is `'webgl'` or `'canvas'`. `game.glStatus()` reports init, the packed light count, and the occlusion-mask count.

## Shader

GLSL ES 3.00, no libraries. Fullscreen triangle (`gl_VertexID` only).

Light pass uniforms:

- `uPos[32]`, `uRad[32]` — screen pixels (origin matches the GL framebuffer). Radius is ellipse-scaled with the view so zoom matches `zoomVis`.
- `uCol[32]` — `LCOL` 0–1. `uAmp[32]` — the light's `a`, clamped to 1.
- `uOcc[32]` — mask layer, or `-1` if that light was already unoccluded on the Canvas path (projectiles, item glints, the small flame core).
- `uCount`, `uResolution`, `uView` (world x, y, w, h of `zoomVis`)
- `uAmbient` `#050408`, `uExplored` `#1a1520`, `uSeen` (one texel per map tile), `uTile` (16)
- `uMask` — `sampler2DArray`, R8, nearest. One layer per distinct visibility polygon.

Falloff is a smoothstep through the same stops as the baked radial gradient (1, 0.92, 0.60, 0.22, 0). An 8×8 Bayer matrix adds ±0.5/255 so the multiply does not band in 8-bit.

Composite pass: `uScene` (the 2D canvas, nearest, re-uploaded each frame, resized only when `VW`/`VH` change) times `uLight`.

## Occlusion

Major lights still carry `poly` / `polys` from `visPoly` / `bandPolys`. The WebGL path rasterizes those polygons into a screen-sized mask:

- Banded lights (`drawLightPolys`) paint each band at `1/n` and add them, so the soft shadow steps stay.
- A single polygon is a hard clip, same as the Canvas path.
- Lights that share one polygon array share one layer.
- Cap is 24 masks and 32 lights (the uniform budget on a minimum WebGL2 device). Past that, extra **occluded** lights are dropped, not drawn through walls. Extra unoccluded lights past 32 are dropped (the dimmest first). Occluded lights are packed first. The Canvas path has no cap.

Masks are nearest-filtered so bilinear samples cannot leak a lit texel across a wall. Edges are the canvas fill's antialiasing, on the order of a pixel, not a room.

## Fallback

WebGL2 missing, shader compile/link failure, context loss, or a framebuffer that will not complete: that frame uses `lcan` and the reason is kept on `glStatus().reason`. A lost context stays on Canvas until the browser restores it. `preserveDrawingBuffer` is on so the copy back onto the 2D canvas is reliable in Safari; that is an extra fullscreen copy.

## Known gaps

- Low quality never uses the shader, by decision. iPhone default is Low.
- The shader is not a byte match of `LGRAD`. Shape of the falloff matches; dither and smooth shoulders do not.
- Unoccluded lights (shots, ground glints, the tiny flame core) can still cross a wall. That is the same as `lcan` today.
- If more than 24 occluded lights are on screen, the extras go dark instead of bleeding.
- No WebGL half-resolution mode. High is full internal resolution (`VW`×`VH`, already a small pixel grid).
- Desktop and iPhone Safari still need a human playtest before merge. This branch was checked with headless Chrome only.

## Playtest (desktop + iPhone Safari)

1. New game, Lighting **High**, GL LIGHT **AUTO**. Torch falloff should be smooth, unlit floor a deep navy, remembered tiles a little lighter, and light should stop on walls (open a door and confirm it spills through).
2. Zoom out (`-` on desktop, including 0.25x). Unexplored rooms stay black. The lit pool stays with the player.
3. Pause, GL LIGHT **OFF**. The frame should jump to the Canvas lightmap (slightly banded gradients). ON / AUTO returns to the shader on High.
4. Lighting **Low**. Path stays Canvas even if GL LIGHT is ON. Phone default is this until High is chosen.
5. iPhone Safari: set High + AUTO. Walk with a torch, a brazier, a fire pit, and a solved prism if one is handy. Confirm flames, eyes, and HUD sit above the dark, and that a reload with WebGL blocked (or Low) still plays.
6. Resize the window and rotate the phone. No stretched light, no permanent black frame.
